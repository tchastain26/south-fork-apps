Stop carrying stale tasks into the next AI session.

Your assistant says a task is finished. The dashboard still says it is open. The next session starts from the dashboard and tries to do the same work again.

The fix starts with a short closeout process. You can use the steps below by hand or ask an assistant to follow them. No purchase is needed.

1. Check the actual result

Start with evidence from the system where the work happened. For a published page, open the live page and check the expected content. For a file, check the saved file. For a task in an external task manager, check the task and its subtasks there.

A statement in chat is a lead to check. It is not, by itself, proof that the work finished. If you cannot check the result, record that it is unverified.

2. Choose one current task record

Give each task a stable name or ID. Keep a small current list that says what is open, done or blocked. Record the evidence and the date checked. Separate the task outcome from its history.

Task: Publish the sample page
State: Done
Evidence: Live page opened and expected sample checked
Task: Test the downloadable file
State: Open
Evidence: Download has not been tested

This is a fictional example. Publishing the page does not prove that its download works.

3. Find the other current mentions

Search the project notes, dashboard and handoff for the same task title and ID. Check alternate names when needed. Decide which mentions claim to show current status. Leave dated history as history.

Update only the current statements that are now wrong. Keep separate work open. Do not close a whole project because one part passed.

4. Compare the before and after

Read the changes before you save or commit them. Check that you changed the intended task, preserved unrelated notes and left unfinished work visible. A text comparison helps you spot an accidental edit; it cannot tell you whether the task really finished.

For non-sensitive text, our free Text Diff tool can show differences. Keep confidential project data in an approved local tool.

5. Leave one clear next action

The next session needs the verified result, what is still open and the next action. It should also know about any access it needs.

Verified: Sample page is published and checked.
Still open: Test the downloadable file.
Next action: Download the file from the live page and open it.
Access needed: None.

When a checklist is enough

For one small project, the five steps may be all you need. A formatting tool such as our Markdown List Cleaner can tidy a list, but it does not check the truth of a task status.

When you need a repeatable check

If the same task appears in several Markdown files, a local checker can compare tagged checkboxes against an explicit task manifest. It can flag a disagreement for review. Someone still needs to verify the real result and maintain the manifest.
